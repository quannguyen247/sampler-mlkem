## 2. Normative references

- NIST FIPS 203, *Module-Lattice-Based Key-Encapsulation Mechanism
  Standard*, August 13, 2024, including published errata applicable to the
  release under verification.
- [`Implementation/rtl/utils/mlkem_sampler_defs.vh`](Implementation/rtl/utils/mlkem_sampler_defs.vh)
- RTL modules under [`Implementation/rtl/modules/`](Implementation/rtl/modules/)

The RTL implements the sampling transformations named `SampleNTT` and
`SamplePolyCBD` in FIPS 203. It consumes bytes already generated by the
required pseudorandom or extendable-output function. It does not generate
SHAKE output itself.

## 3. Scope and non-goals

### 3.1 Scope

- `sample_ntt`: rejection-samples 256 coefficients in `[0, q-1]` from a byte
  stream.
- `sample_poly_cbd`: samples 256 centered-binomial coefficients for `eta=2`
  or `eta=3` and emits their canonical modulo-`q` representation.
- `mlkem_sampler_top`: selects one sampler and exposes a common streaming
  interface.

Constants are `q = 3329`, coefficient width 12 bits, and coefficient count
256.

### 3.2 Non-goals

The current RTL does not provide:

- SHAKE/XOF generation, PRF expansion, seed/nonce handling, or entropy input.
- NTT arithmetic; `SampleNTT` is a sampler that produces coefficients intended
  for the NTT-domain polynomial representation.
- Polynomial memory, matrix generation, vector sequencing, or a complete
  ML-KEM accelerator.
- AXI4, AXI4-Lite, AXI4-Stream, APB, DMA, or a register map.
- An error/status code for illegal requests or input exhaustion.
- A timeout or maximum-byte bound for rejection sampling.
- Masking, hiding, fault detection, secure zeroization, or a side-channel
  resistance claim.

## 4. Modes and representations

### 4.1 Mode encoding

| `mode` | Macro | Operation |
|---:|---|---|
| `2'b00` | `MLKEM_SAMPLER_MODE_NTT` | `SampleNTT` |
| `2'b01` | `MLKEM_SAMPLER_MODE_CBD_ETA2` | `SamplePolyCBD`, `eta=2` |
| `2'b10` | `MLKEM_SAMPLER_MODE_CBD_ETA3` | `SamplePolyCBD`, `eta=3` |
| `2'b11` | none | Unsupported; start is ignored |

### 4.2 Byte and coefficient representation

- Bytes are accepted in increasing algorithmic byte order.
- In `SampleNTT`, each group `(b0,b1,b2)` forms:
  - `d1 = b0 + 256 * (b1 & 15)`;
  - `d2 = (b1 >> 4) + 16 * b2`.
- `d1` is considered before `d2`; each candidate is emitted only if `< 3329`.
- In `SamplePolyCBD`, input bytes are interpreted as a little-endian bit
  string. Within each coefficient, the first `eta` bits form population count
  `a` and the next `eta` bits form population count `b`.
- CBD output is `(a - b) mod 3329`, encoded as an unsigned 12-bit value in
  `[0, 3328]`. Thus negative centered values are represented by adding `q`.
- Output order is coefficient index 0 through 255.

## 5. Functional requirements

| ID | Requirement |
|---|---|
| SAM-FUNC-001 | Every accepted supported operation shall emit exactly 256 accepted coefficient transfers. |
| SAM-FUNC-002 | `SampleNTT` shall parse each three-byte group into `d1` and `d2` as specified in Section 4.2. |
| SAM-FUNC-003 | `SampleNTT` shall emit valid candidates in `d1`, then `d2` order and reject candidates greater than or equal to `q`. |
| SAM-FUNC-004 | `SampleNTT` shall stop immediately after the 256th coefficient; no trailing input byte is required or consumed. |
| SAM-FUNC-005 | CBD `eta=2` shall consume exactly 128 accepted input bytes and emit two coefficients per byte. |
| SAM-FUNC-006 | CBD `eta=3` shall consume exactly 192 accepted input bytes and emit four coefficients per three-byte group. |
| SAM-FUNC-007 | CBD shall compute each coefficient as the difference of two `eta`-bit population counts modulo `q`. |
| SAM-FUNC-008 | `coeff_last` shall qualify the 256th coefficient while `coeff_valid` is asserted. |
| SAM-FUNC-009 | Mode `2'b11` shall not start an operation and shall leave `busy`, `done`, `byte_ready`, and `coeff_valid` low. |

## 6. Top-level interface

Module: `mlkem_sampler_top`

| Port | Dir. | Width | Semantics |
|---|---|---:|---|
| `clk` | in | 1 | Rising-edge clock. |
| `rst_n` | in | 1 | Active-low synchronous reset. |
| `mode` | in | 2 | Operation mode, sampled by a supported start. |
| `byte_valid` | in | 1 | Qualifies `byte_in`. |
| `byte_in` | in | 8 | Next input byte. |
| `byte_ready` | out | 1 | Selected sampler is ready to accept a byte. |
| `coeff_ready` | in | 1 | Consumer is ready to accept a coefficient. |
| `coeff_valid` | out | 1 | Qualifies `coeff_out` and `coeff_last`. |
| `coeff_out` | out | 12 | Canonical coefficient modulo `q`. |
| `coeff_last` | out | 1 | High with coefficient index 255. |
| `start` | in | 1 | Starts a supported operation while idle. |
| `busy` | out | 1 | High while an operation is active, including the `done` cycle. |
| `done` | out | 1 | One-cycle completion indication after the last accepted coefficient. |

The submodules expose the same stream/control concepts. `sample_poly_cbd` has
an `eta[1:0]` input; any value other than 3 is internally treated as 2.

## 7. Protocol and reset behavior

| ID | Requirement |
|---|---|
| SAM-IF-001 | A supported operation shall start on a rising edge with `start && !busy`. |
| SAM-IF-002 | `mode` shall be latched for the active top-level operation. |
| SAM-IF-003 | An input-byte transfer shall occur only on a rising edge with `byte_valid && byte_ready`. |
| SAM-IF-004 | The producer shall hold `byte_valid` and `byte_in` stable until transfer. |
| SAM-IF-005 | A coefficient transfer shall occur only on a rising edge with `coeff_valid && coeff_ready`. |
| SAM-IF-006 | While `coeff_valid && !coeff_ready`, `coeff_out` and `coeff_last` shall remain stable. |
| SAM-IF-007 | `start` asserted while `busy` is high shall be ignored. |
| SAM-IF-008 | `done` shall be high for one cycle. In that cycle `busy` is also high; both are low after the next active clock edge. |
| SAM-IF-009 | Reset shall synchronously return the top and selected submodules to idle, clear counters/data registers, and deassert handshake/status outputs after the reset edge. |
| SAM-IF-010 | The IP has no error output. Unsupported mode is ignored; insufficient input causes the operation to wait indefinitely for more bytes. |

There is no input-side backpressure while a byte is being requested beyond
`byte_ready`. Integrations shall not infer that `byte_valid` is accepted when
`byte_ready` is low.

## 8. Microarchitecture

### 8.1 `sample_ntt`

The eight-state controller loads three bytes, evaluates two 12-bit candidates,
and conditionally enters one or two output states. Candidate registers remain
stable during output backpressure. A 9-bit counter tracks accepted
coefficients.

### 8.2 `sample_poly_cbd`

The four-state controller loads one byte for `eta=2` or three bytes for
`eta=3`, then emits two or four coefficients. Population counts are
combinational. The input group and coefficient index remain stable during
output backpressure.

### 8.3 `mlkem_sampler_top`

The top latches the selected mode and gates the common byte/coefficient
interfaces to one submodule. Unsupported mode does not set `active_r`.
Submodule `busy` outputs are not used by the top.

## 9. Performance contract

Performance below assumes continuous input availability and
`coeff_ready == 1`. A cycle is counted from the accepted start edge through
the edge that enters the `done` state.

| ID | Mode | Input accepted | Output accepted | No-stall latency |
|---|---|---:|---:|---:|
| SAM-PERF-001 | CBD `eta=2` | 128 bytes | 256 coefficients | 384 cycles |
| SAM-PERF-002 | CBD `eta=3` | 192 bytes | 256 coefficients | 448 cycles |
| SAM-PERF-003 | SampleNTT | `3G` bytes | 256 coefficients | `4G + 256` cycles |

`G` is the number of three-byte groups required to obtain 256 candidates below
`q`. Rejection sampling makes `G` and total SampleNTT latency data-dependent
and unbounded if a source never supplies enough accepted candidates.

Each input stall adds one cycle per stalled requested byte. Each output stall
adds one cycle per stalled coefficient. The RTL does not overlap loading a new
group with coefficient emission. This is requirement `SAM-PERF-004`.

Clock frequency, KV260/K26 timing, ASIC timing, and achieved throughput are
**UNVERIFIED**.

## 10. Memory and resource contract

The RTL contains no explicit BRAM, URAM, SRAM macro, LUTRAM primitive, DSP
primitive, or multiplier. Storage is limited to small registers and counters
in source RTL. Synthesis mapping is tool- and target-dependent.

LUT, FF, BRAM, URAM, DSP, area, power, and Fmax are **UNVERIFIED**. Any
resource claim shall cite matching post-synthesis and post-route reports.

## 11. Security requirements and limitations

| ID | Requirement |
|---|---|
| SAM-SEC-001 | Documentation and verification reports shall not claim FIPS validation or complete ML-KEM validation. |
| SAM-SEC-002 | Documentation and verification reports shall not claim side-channel or fault-attack resistance. |
| SAM-SEC-003 | The byte source shall provide the exact FIPS 203-defined pseudorandom/XOF input and domain separation for the selected sampling operation. |
| SAM-SEC-004 | A production integration shall define reset, abort, completion, and retained-data zeroization requirements. |
| SAM-SEC-005 | Rejection-sampling runtime shall be treated as data-dependent; any system-level timing-leakage claim requires separate analysis of whether the sampled stream is secret and of the enclosing protocol. |

The current implementation is unmasked, has no redundancy or fault alarms,
and retains internal group/candidate data until overwritten or reset.

## 12. Integration assumptions

- All ports belong to one clock domain.
- Reset release is synchronous to `clk` or synchronized externally.
- Upstream Keccak/SHAKE logic supplies bytes in exact algorithmic order.
- The upstream source can continue supplying SampleNTT bytes until 256
  candidates are accepted.
- The consumer accepts canonical modulo-`q` coefficients and uses
  `coeff_last` to identify polynomial completion.
- Any buffering, memory addressing, bus wrapper, timeout, retry, interrupt,
  or error handling is outside this IP.
- Parameter-set sequencing (`ML-KEM-512`, `ML-KEM-768`, `ML-KEM-1024`) is
  outside this block; the same sampler primitives are selected by the
  enclosing controller as required by FIPS 203.
